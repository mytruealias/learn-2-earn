## Implemented behavior

Learner reads/saves, staff requests and public intake now use a bounded **non-streaming** transport. The deadline covers the response body and composes caller cancellation; callers keep their own validation, intent keys and state machines. It has no automatic retry, mutation queue or response storage. Streaming Hubert chat keeps its existing bounded streaming/cancel flow; availability/help reads and optional cloud audio use the bounded transport. No service worker, offline monetary credit, automatic payment replay or notification provider was added.

The shared connection notice distinguishes offline, slow, failed and apparently restored connectivity. It does not claim a save or that every background request stops. Unsaved answers/financial requests are not queued for replay. Users keep the screen open, use its explicit retry or check authoritative history. Help remains a real destination. Correlation references from failed responses contain only validated opaque IDs. Dynamic notice/header/nav measurements reserve focus/scroll space; the staff mobile menu stays below the visible notice. Staff page entry and restored back-navigation recheck the server session; an unconfirmed/revoked session hides records, and failed sign-out never claims revocation or redirects as success. Continuous foreground/session revalidation that preserves unsaved private modal state remains a separate verification item; no background visibility handler now unmounts an in-progress staff form.

Shared dialogs honor disabled-close explanations through button, Escape and backdrop consistently. Missing headings in staff overview/participant/case loading/error states and shared session failures are corrected. Profile save feedback persists with status/alert semantics, save uses the shared busy control, controls have minimum target geometry, narrow form rows wrap, and badge explanation no longer describes losing hearts. The legacy staff toast provider has no current caller found, but its timer/unnamed close/non-live roles were fixed; actual shared Toast remains the preferred consumer. Generic route, staff, root-layout and missing-page recovery provide meaningful headings, retry/help destinations and no false save claim. Root recovery is standalone if layout styles fail.

Home calculates pathway summaries on the server: the browser receives counts/minutes/path labels rather than the entire lesson-metadata tree and completed-ID list. A measured 200-lesson synthetic serialization case changes **29,117 → 177 bytes (99.39%)**; [evidence](payload-evidence.json) is not a production bundle or latency measurement. Practice loads cards only for that learner’s completion/review lesson IDs and uses maps instead of repeated array scans. Existing staff pagination and single-current-card lesson payloads are preserved. Root font loading is one variable Inter family; unused terminal/condensed families were removed. No authored curriculum or assessment/reward semantics changed. No speculative query index was added; the new rate table’s primary key is required for atomic admission.

## Distributed limits and database behavior

The additive `HttpRateLimit` model stores only HMAC keys, counts and UTC reset times. Admission is a PostgreSQL UPSERT with a bounded interactive transaction, 3-second statement / 1-second lock deadline. Limits work across instances sharing PostgreSQL and SESSION_SECRET; no in-memory fallback is used. Database/store failure returns 503 without granting access. Database connection/pool waits are capped at five seconds, preserving shorter configured values; existing explicit transaction budgets override the general 5-second wait / 15-second transaction defaults. This is not a global statement timeout for every ordinary query; review host/role query budgets before release.

Established thresholds remain: learner login 10 / 10 minutes, program access 15 / 10 minutes, city PIN 10 / city / 10 minutes, signup 8 / hour, guest creation 20 / hour. Failed-only login/access/PIN gates reserve an in-flight slot and refund **only that request’s** slot after success, preserving other failures. Duplicate local refunds do nothing; an old window cannot decrement a new one. Signup/guest creation continue charging admitted attempts. Existing staff auth, support quotas/leases and partner inquiry limits already use PostgreSQL and remain separate. No financial rate/cap/economics changed.

[Exact SQL/service evidence](rate-store-evidence.json): 24 concurrent requests through two PostgreSQL sessions (different session timezones) admitted five at cap five; retries/expiry, own-slot refund, duplicate/old-window refund, identity isolation, positive-count constraint and approximately one-second lock failure were checked against the real service function using a parameterized pg adapter in a freshly created restricted database. It was nonce/owner/server verified and removed. This does **not** substitute for the generated Prisma/API suite, which is blocked.

Ingress IP trust remains an operational gate: the inherited getClientIp reads proxy headers. Verify the real Replit/proxy overwrites/appends trusted client identity and cannot be spoofed; multi-instance storage alone is not a complete Internet-abuse defense. Shared devices/NAT require program-appropriate operational monitoring. SESSION_SECRET must agree across instances; rotation changes HMAC keys. Expired buckets are reused but no deletion scheduler is configured. Approve bounded retention/maintenance before rollout; a separate reviewed operation can delete expired buckets, never application records. Counter data is global infrastructure metadata and is not exposed through scoped staff record APIs.

## Correlation, errors and health

Middleware replaces incoming request IDs with opaque random IDs, forwards them to the request and returns x-l2e-request-id. All API/redirect responses are private/no-store. Standard, reward and lesson failures use the same reference in their safe response/log channel; operational logs contain only fixed event category, allowlisted operation or sanitized route template and reference. They do not contain exception text, stack, URL/query, headers, learner/case/payment/chat content or credentials. Prisma query logging is explicitly off; framework/host/APM logging remains outside this application-channel guarantee and must be reviewed. Next 15’s installed instrumentation hook/type was inspected; the hook records sanitized framework failures, not error objects.

`OPERATIONAL_TELEMETRY_ENABLED` defaults off. Enabling the optional client channel requires the reviewed flag at **build and runtime** for prerendered/shared layouts; runtime-only changes may leave a previously rendered layout disabled until rebuild/reload. Build does not call the endpoint. The browser sends only fixed client_error/client_rejection and an allowed route template, at most once per 30 seconds per tab; no error value, stack, content, query, identifier, storage or offline queue. The server validates same origin, strict fields, 512-byte/5-second body bound and 12 new reports/IP/minute in PostgreSQL. No third-party analytics or provider was added. Operator review must cover lawful use, access, logging, retention and ingress before enabling it. The privacy summary states this behavior without a zero-retention promise.

- `/api/health/live` GET: process route is live, no database/provider/secret values.
- `/api/health/ready` GET: required signing/MFA-key shape, bounded PostgreSQL transaction and core table presence; returns only ready or generic 503, never configuration details. It does not verify organization mapping, financial reconciliation, actual MFA enrollment, policy approval, providers, staffing or full migration history. Host readiness polling should be bounded and access/rate protected at ingress.
- `/api/telemetry` POST: optional strict technical-error endpoint; default 404, not a support inbox.

Shared JSON parsing now bounds ordinary requests at 64 KiB / 5 seconds; profile-session/MFA parsing is separately limited to 4 KiB. Existing support/inquiry/provider-specific smaller limits remain. Query/body validation and per-endpoint permissions remain server-owned.

## Production laboratory and field goals

It refuses an unmarked or production/development target, missing/stale production artifact, pre-existing server or redirected/error representative route. No real-user performance telemetry was configured, so no field result is claimed. [Lab status](lab/README.md).
