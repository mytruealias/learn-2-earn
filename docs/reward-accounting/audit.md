No source-defined two-person requirement was found: role separation exists, and the HTTP regression explicitly has one admin review and approve. Preserve role permissions; support an explicitly configured distinct-reviewer rule without silently imposing it on existing programs. Existing default payment methods remain the four executable manual methods. Zelle can be enabled only explicitly through a staff-confirmed manual workflow; schema/history keep it. No automated payment integration is claimed.

Implementation must preserve lifetime totalXp, first Progress, payout IDs/history, configured rates/minima/caps and manual pool balance. Introduce additive exact fields and audited XP reservations; round legacy recorded dollars once, half up to cents, never reprice them using current rules. Explicit dry-run/hash-confirmed backfill/reconciliation is separate from build and migration. Unknown statuses, overspent accounts, invalid amounts and unexplained XP differences require operator review, not silent repair. No production backfill or reconciliation is claimed complete by source changes or disposable tests.

Additional source findings: `app/api/admin/users/[userId]` let any authenticated staff overwrite totalXp with a clamped adjustment, with audit outside the write. `app/api/user/profile` lets learners edit city, which originally selected their money terms. The implementation must ledger authorized entitlement corrections without rewriting lifetime learning history, and bind financial programs separately from self-edited contact city. Existing legacy city mappings must be verified during explicit reconciliation; this is not a claim of full partner/tenant isolation.
